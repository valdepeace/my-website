# AGENTS.md

Context for AI coding agents (Claude Code, Codex, etc.) working in this repo.
See also `CLAUDE.md`, which points here.

## What this is

Andrés Carmona Gil's personal website: a [Docusaurus](https://docusaurus.io/)
3 site with a blog, an About Me page, and a Projects page. No docs plugin
(`docs: false`). Bilingual: English (default locale) + Spanish (`es`).
Deployed to GitHub Pages at `valdepeace.com`.

## Tech stack

- Docusaurus 3.9.2 (`@docusaurus/preset-classic`) + `@docusaurus/theme-mermaid`
  (mermaid code fences render as diagrams)
- React 19 + TypeScript ~5.6.2
- Node `>=20` (`engines` in `package.json`; CI uses Node 20)
- Package manager: npm (`package-lock.json` is the lockfile; no
  `packageManager` field, no yarn/pnpm lockfiles)
- No test framework and no ESLint/Prettier config exist in this repo. Don't
  invent `npm run lint` / `npm test` — they aren't defined.

## Commands

All from `package.json` — these are the only scripts that exist, don't
assume others:

- `npm start` — `docusaurus start`, dev server at `localhost:3000`
- `npm run build` — `docusaurus build`, production build into `build/`
- `npm run serve` — `docusaurus serve`, preview a production build
- `npm run typecheck` — `tsc --noEmit`
- `npm run clear` — `docusaurus clear` (wipe cache/generated files)
- `npm run swizzle` — `docusaurus swizzle`
- `npm run deploy` — `docusaurus deploy` (manual GH Pages push; normally
  unnecessary, see Deploy below)
- `npm run write-translations` / `npm run write-heading-ids` — Docusaurus
  i18n/heading-id helpers

After any code or content change, run `npm run typecheck`, and
`npm run build` when feasible to catch broken links/refs. `onBrokenLinks` is
set to `'warn'` (see below), so a broken link won't fail the build — check
the build output for warnings anyway.

## Repo structure

- `blog/` — English blog posts (default locale), plus `authors.yml` and
  `tags.yml`
- `i18n/es/docusaurus-plugin-content-blog/` — Spanish blog: **every** post in
  `blog/` must have a matching file here (same filename/date), plus its own
  `authors.yml`, `tags.yml` (label/description overrides), `options.json`
- `i18n/es/docusaurus-plugin-content-pages/` — Spanish translations of
  `src/pages/*.md`
- `i18n/es/docusaurus-theme-classic/` — `navbar.json` / `footer.json` label
  overrides for Spanish UI strings
- `src/pages/` — standalone pages: `index.tsx` (homepage), `about.md`,
  `projects.md`, `markdown-page.md`
- `src/components/` — `CodeBackground`, `HomepageFeatures` (used by
  `index.tsx`)
- `src/css/custom.css` — global theme overrides
- `static/` — copied as-is into the build: `CNAME` (`valdepeace.com`),
  `.nojekyll`, `img/`, and placeholder `blog/rss.xml` +
  `es/blog/rss.xml` (committed so localized RSS links don't 404 before the
  next real build regenerates them — leave them in place)
- `docusaurus.config.ts` — site config: title/tagline, `i18n.locales = [en,
  es]` with `en` default, navbar/footer, blog preset options
  (`postsPerPage: 'ALL'`, `onBrokenLinks`/`onInlineTags`/`onInlineAuthors`/
  `onUntruncatedBlogPosts` all `'warn'`)
- `blogSidebar.js` — custom blog sidebar (autogenerated post list + an
  "Authors" link)
- `.github/workflows/deploy.yml` — on push to `main`: `npm ci`,
  `npm run build`, then `peaceiris/actions-gh-pages` publishes `build/` to
  the `gh-pages` branch

## Blog post conventions

**Every English post in `blog/` needs a matching Spanish post in
`i18n/es/docusaurus-plugin-content-blog/`** with the same filename (same
`YYYY-MM-DD-slug.md` date + slug) and a translated `title`/`description`.
Don't add one without the other.

Two frontmatter shapes coexist in the existing posts; prefer the newer one
for new posts:

- Older/simple (e.g. `welcome.md`, `over-engineering-vs-poc.md`):
  `slug`, `title`, `authors: [valdepeace]`, `tags: [...]` — explicit slug,
  no `description`, no explicit `date`.
- Newer/preferred (e.g. `cardboard-architecture.md`,
  `mastra-azure-ai-search.md`): `title`, `description`, `authors:
  ["valdepeace"]`, `date: "YYYY-MM-DD"`, `tags: [...]` — no explicit `slug`
  (Docusaurus derives it from the filename); includes an SEO
  `description`.

Other rules:

- Always set `authors: [valdepeace]` (defined in `blog/authors.yml` and its
  i18n twin) unless you're deliberately adding a new author to
  `authors.yml` first.
- Always include `<!--truncate-->` after the first 1–3 sentences —
  `onUntruncatedBlogPosts: 'warn'` flags posts missing it.
- Voice: first-person, informal-but-technical, matching the existing posts.
  The Spanish version should read as a natural translation (tuteo, not
  "usted"), not a literal machine translation.

**Tags**: reuse an entry from `blog/tags.yml` (and its i18n/es twin) before
inventing a new one. Note the existing tag keys are a mix of English and
Spanish spellings depending on which locale's posts use them (e.g.
`architecture`/`best-practices` for English posts vs.
`arquitectura`/`buenas-practicas` for Spanish posts, while others like
`refactor`, `mastra`, `personal`, `open-source` are shared as-is across both
locales with only the label translated). Check both the English post's tags
and its Spanish sibling's tags in existing posts before picking keys for a
new one. If you do add a new tag key, add it to **both** `blog/tags.yml` and
`i18n/es/docusaurus-plugin-content-blog/tags.yml` with the same key and a
locale-appropriate `label`/`description` in each.

**Authors**: reuse `valdepeace` from `blog/authors.yml` before adding a new
author entry.

## Other conventions

- Deploy is automatic on push to `main` via `.github/workflows/deploy.yml`
  (build → publish `build/` to `gh-pages`). `npm run deploy` is only for
  manual out-of-band deploys.
- `static/CNAME` pins the custom domain (`valdepeace.com`) — don't remove
  it.
- `trailingSlash: false`, `baseUrl: '/'`, `organizationName: 'valdepeace'`,
  `projectName: 'my-website'` are GitHub Pages settings — don't change them
  without understanding the deploy impact.
